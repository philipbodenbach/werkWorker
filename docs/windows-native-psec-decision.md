### Native enforcement contract

The audited Microsoft MXC revision is `51805f40beaf19631df63ae25d0c11876d05a4ce`. The diagnostic explicitly used `CreateProcessSecurityEnvironment`, attached `PROC_THREAD_ATTRIBUTE_SECURITY_ENVIRONMENT` at `CreateProcessW`, and observed successful creation of the environment and suspended roots. It used the existing policy encoder. Its 12 generated schema files matched the Microsoft revision after line-ending normalization. The launch ran directly against the OS without SDK backend selection or fallback. [Microsoft support table](https://github.com/microsoft/mxc/blob/51805f40beaf19631df63ae25d0c11876d05a4ce/docs/backends/process-container/os-version-support.md) · [Native API flags](https://learn.microsoft.com/en-us/windows/win32/api/processmodel/ne-processmodel-process_security_environment_support_flags)

**Filesystem.** The submitted FlatBuffer requested read/write access for the two fixture directories, read-only access for the fixture runtime and System32, and denies for the C: and F: volume roots. It specified Win32k denial, UI mask `0x3ff`, zero explicit capabilities and default-deny network rules. Microsoft documents ambient AppContainer grants, equal-path deny precedence, and narrower explicit writable grants under a parent deny. Its volume-root exception is documented for grants. The measured permission checks do not exercise the PSEC filesystem filter. The earlier same-build test did observe an explicit image deny take effect. Coverage across file identities, alternate paths, mounted volumes and previously granted handles remains a prerequisite for an exclusive write scope. [Microsoft filesystem model](https://github.com/microsoft/mxc/blob/51805f40beaf19631df63ae25d0c11876d05a4ce/docs/backends/process-container/filesystem.md) · [Path precedence](https://github.com/microsoft/mxc/blob/51805f40beaf19631df63ae25d0c11876d05a4ce/docs/schema.md#L450-L521) · [Measured image deny](evidence/windows-process-tree-2026-11-14/psec-native.log)

**Registry.** The pinned PSEC schema and mapper expose neither a host-key write scope nor a selectable private hive. BaseContainer rejects a request for LPAC. Microsoft's Registry control reads a host value with an explicit `registryRead` capability. The WerkWorker requirement is an inherited write boundary, including the package profile and persistent host state. The observed discretionary grants would require an additional OS enforcement or virtualization guarantee. No such guarantee was established for this PSEC tree. ### Integration decision

This host-Job design requires a Windows enforcement point that bounds persistent Registry writes for the entire process tree, or a private Registry with demonstrated isolation from host state. It also needs a hard admission limit that includes system-created console helpers. A new protocol field alone cannot supply either property.
